# add-monthly-roster-import · Design

## Context

既有底座:步骤 2 已合并(common 统一响应/JWT 认证/`requireAdmin()`、staff 418 人档案与工号匹配规则、EasyExcel 3.3.3 依赖);`monthly_roster`(uk_roster_month 唯一)/`monthly_roster_item`(duty_date + seq 双形态)两表已就绪,**无 schema 变更**。动机见 proposal.md - Why;需求行为见 specs/monthly-roster/spec.md;完整决策过程见已批准设计文档 `docs/designs/monthly-roster-import.md`(三轮评审 9/10)。

## Goals / Non-Goals

**Goals**:真实月表 100% 可解析入库;解析/校验/导入/替换全链路可测;解析适配层的格式假设集中在一处,样本校准只动这一处。

**Non-Goals**(设计级边界):不做服务端预览会话暂存;不做解析规则配置化 UI;不做在线编辑(方案 B);不处理排班快照失效(仅时间戳提示)。

## Decisions

### D1 两阶段无状态交接(parse → import)
- **选择**:parse 返回完整行集合(行标识 = sheet 名 + Excel 物理行号),前端持有并回传修正后的完整集合;服务端不暂存解析会话。
- **理由**:无会话生命周期/过期清理问题;月表约 300 行/月,回传体积可忽略;与系统"前端持有、后端复核"的交互风格一致。
- **备选**:服务端暂存解析结果 + 修正补丁(差量)——省流量但引入会话状态与过期语义,对单用户月度操作是过度设计。

### D2 解析适配层:EasyExcel 主通道 + POI 兜底
- **选择**:常规单元格走 EasyExcel 流式读取;合并区域走 POI(`getMergedRegions()`,EasyExcel 传递依赖,零新增)做坐标→语义重建;sheet/列/合并映射规则先用常量集中在 `RosterFormatAdapter` 一处。
- **理由**:EasyExcel 默认合并区域仅左上格有值,直接读会静默错位;格式假设收敛一处,真实样本到位后校准成本最小;若科室格式频繁变化,升级为配置只是这一层内部的事。
- **备选**:全 POI 手写解析——控制力最强但样板代码多;纯 EasyExcel + 人工预览纠错——静默错位风险不可接受(spec 明令禁止)。

### D3 人员匹配复用 staff 查询
- **选择**:姓名 → 在职 staff 检索(唯一名直接解析;同名出候选;单元格含工号优先),通过复用/内调既有 staff Mapper 查询实现,不复制匹配代码。
- **理由**:匹配规则与步骤 2 同源(假设 A6),避免两套规则漂移。

### D4 替换语义:事务删重插 + 业务幂等
- **选择**:同月导入在单事务内删旧 item 全量重插;幂等口径 = 替换后业务数据等价(item 自增 id 允许变化);`monthly_roster.status` 导入即 ACTIVE(无草稿态)。
- **备选**:月表版本化(version 列)——schema 无此列,属方案 B 范围,显式不做。

### D5 校验引擎输出结构
- **选择**:每条问题为 `{级别: 阻断|警告, 行定位: sheet+物理行号, 消息, 修正类型: 人名候选|岗位映射|日期对齐|无}`,前端按修正类型白名单渲染可修正控件,其余问题只能回 Excel 改后重传。
- **理由**:修正类型是前后端契约,白名单防止实现滑向在线编辑(方案 B)。

### D6 三类待校准岗位的默认形态
- **选择**:LONG_RELIEF/ASSISTANT_RELIEF/ASSISTANT_MID 默认 duty_date 按日;校准点收敛在 D2 的适配层与落库映射表,样本到位后只改映射不改结构。

## Risks / Trade-offs

- [真实月表格式未见过,映射规则是假设] → 样本到位后仅校准 `RosterFormatAdapter`;首版验收线 = 目标样本 100% 可解析,不求普适
- [合并单元格语义重建复杂度可能超预期] → POI 兜底通道已预留;适配层单测用样本逐区域断言
- [预览修正链路为全新工作量(步骤 2 无可搬用件)] → 估算按人工 6-10 天 / CC 2-3 轮;若样本校准阶段发现解析质量高,可将预览降级为只读确认
- [重传整月覆盖无历史版本] → 过渡期追溯靠人工留存 Excel;版本化留给方案 B

## Migration Plan

无数据库变更、无外部依赖变更:随常规发布部署;回滚 = 停用新版本即可,既有数据不受影响(替换只作用于月表两表)。

## Open Questions

1. 短接班顺序在真实表中的呈现(独立列?日期矩阵?)→ 样本到位后在校准适配层时确定,不影响 spec 行为
2. 月表是否多 sheet/多月并存 → 同上,校准解析入口
3. 周末/节假日值班四档是否必须齐全 → 已定为警告级,科室口径确认后可调整级别,不改结构
