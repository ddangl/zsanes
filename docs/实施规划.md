### 排班引擎设计原则

1. **规则管道**:请假确认(二期)→ 值班组 → 接班/备班 → 手术室分配 → 外围轮转(二期)→ 咨询(二期)→ 肝移植编组(二期)。每一步消费上一步产出的"当日人员占用",保证一人不双岗。
2. **随机可复现**:所有随机环节使用统一随机种子(seed),同数据 + 同 seed 生成结果一致;seed 随排班快照落库,便于回溯与重新生成。
3. **人工调整覆盖层**:引擎产出 `AUTO` 结果;总值班手动修改生成 `MANUAL` 覆盖记录并留痕(改前快照),不回写引擎。
4. **参数数据化**:特殊人员名单、固定房间分配、预留间数等全部存配置,不写死代码——需求确认后改数据即可(升级:由规则中心统一承载,见 4.7)。
5. **失败重试**:任一环节排不下时整体重试(默认上限 20 次),仍失败则返回具体的缺人/缺房明细,不静默出错。

### 4.4 排班引擎步骤(一期)

输入:日期 + seed;输出:DRAFT 快照。

```
0. 可用人员池 = 在职 − 当日休息/手动排除(手术室环节另剔除主任)
1. 值班组(月表当日 1老总+1二档+1三档+1四档)最先放入
   → 自动标记次日 REST_AFTER_CALL
2. 备班1(月表当日)→ 固定房间段(读配置)
3. 短接班:从顺序池顺延取人,与备班1同人则跳到下一位;不可用人跳过
4. 长接班;副麻接班(周一~四复制前一日已确认结果,周五重置);副麻中班
5. 手术室分配:
   a. 剔除主任
   b. 固定分配(读配置:陆珠凤→22–29、备班1→802–825)
   c. 按特殊人员名单预留单间(间数读配置)
   d. 主麻随机抽取(seed),有亚专科者优先匹配对应专科房间,直到剩余房间=预留数
   e. 特殊人员进单间
   f. 副麻分配:带教学生优先配自己的主麻 → 剩余房间按"先大后小"随机配
      → 星标房优先配高级别副麻(按假设 A1:5 级最高)
   g. 任一环节排不下 → 整体重试(≤20 次);仍失败返回缺人/缺房明细
6. 落库 DRAFT → 工作台手动调整(逐条留痕)→ 总值班确认 CONFIRM
```

### 4.7 规则中心(Rule Center)设计(2026-09-09 定稿)

**背景**:科室规则持续以自然语言下发(房间清单、人员特殊说明等),人员与规则均靠手工维护。规则中心让总值班在界面上维护规则,并让系统真正"读懂"。

**已确认决策**:结构化为主 + 自然语言原文存档(不依赖 AI,院内网离线可用);仅总值班 ADMIN 可维护,不新增角色。

**核心设计**:

1. **双形态规则模型**:每条规则 = `nl_text`(科室原话,给人看、可追溯)+ `payload`(JSON 结构化参数,给引擎执行)。编辑用按 rule_type 生成的分类表单(选人/选房间/选岗位一律用选择器,杜绝手输),保存前做引用完整性校验(工号/房间/岗位必须存在),并**反向生成中文回读预览**供维护人核对。
2. **RuleRegistry(策略模式)**:每种 rule_type 注册一个 RuleHandler,声明挂载点(引擎管道哪一步)与 payload 解释逻辑。引擎只读 ACTIVE 规则的结构化 payload,不接触自然语言。
3. **版本快照可追溯**:规则每次"发布"生成 rule_version;排班生成时把当次生效规则集(code + version)写入 `schedule.rule_snapshot`——任何历史排班都能回溯"当时规则是什么"。
4. **未结构化兜底**:rule_type=MANUAL_REMINDER 的规则(如"专家门诊可能需老总手动调整")在排班工作台显示为提醒卡,由总值班人工处理;规则永不静默丢失。
5. **统一配置来源**:原 schedule_config(固定分配/特殊单间/预留间数/重试上限)并入规则中心后**废弃**,全系统仅一处维护业务规则。

### 4.8 手术室分布图示模块(Layout Map)设计(2026-09-09 定稿)

**目标**:各区域手术室空间布局可视化、可自绘;主麻分配结果在图上按空间关系呈现——**肩并肩 / 面对面 / 背对背 / 劈叉(同一主麻名下房间不相邻或跨区域)**一眼可辨,总值班据此判断分配合理性并手动修正。

**已确认决策**:邻接关系由绘制几何自动推导 + 手动修正;与引擎联动 = 可视化预警 + 软约束(非硬约束);布局绘制支持上传底图描摹。

**关系推导(AUTO)**:同一行相邻 = 肩并肩;隔走廊两行相对 = 面对面;相邻行背靠 = 背对背。保存布局时重算 AUTO 关系并保留已有 MANUAL 修正。同一主麻的房间**不相邻或跨区域 = 劈叉**。

**布局编辑器**(前端 `views/layout/`):
- SVG 网格画布自研(不引第三方画布库):从房间列表拖拽房间格入图、移动对齐、删除;89 间房已按区域预置,可一键生成两排初始布局再微调
- **底图描摹**:上传医院平面图/照片作半透明背景,把房间格摆到真实位置;底图文件存后端本地静态目录(院内网,不依赖外部存储)
- 邻接线预览:肩并肩/面对面/背对背以不同线型显示,确认推导符合实际

**排班联动**:
- **画布模式**(工作台房间视图新增):当日排班渲染在区域图上——同一主麻的房间同色描边 + 角标,副麻显示在房间格内;**劈叉组标红**,工作台顶部显示"劈叉组数"指标
- **软约束**:规则中心新增 `OR.ADJACENCY_PREF`(payload:{enabled, weights:{肩并肩 > 面对面 > 背对背}, split_penalty}):主麻房间组合分配时按邻接关系加权,劈叉受罚但不禁死;开关与权重在规则中心维护。权重排序与劈叉容忍度待科室确认(业务规则待确认 #15)

**排期**:实施步骤 7(见第 5 节)——布局编辑器不依赖排班引擎可先行,画布模式与软约束随工作台/引擎接线。

## 6. 验收标准(一期)

1. 导入月度表 → 一键生成某工作日排班,**无一人双岗、无房间超配**冲突
2. 手动改一人,留痕完整(能看到改前/改后/操作人)
3. 确认后周视图与 Excel 导出内容正确
4. 引擎单元测试全部通过;同 seed 重复生成结果一致
5. 普通成员登录只能查看,不能修改
6. 规则中心:规则可维护、发布产生版本;生成排班时规则快照可回溯;引用不存在的人员/房间时校验拦截并提示
7. 图示模块:绘制某区域布局并上传底图,邻接关系自动推导正确且可手动修正;画布模式按主麻染色、劈叉组标红;软约束开启后重新生成,劈叉组数下降

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 需求存在 11 项待确认(业务规则.md 第 10 节) | 所有存疑规则参数化(schedule_config),确认后改数据即可;假设 A1~A5 已文档化 |
