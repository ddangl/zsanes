## 1. 总览:一条请求的完整旅程

理解这张图,前后端如何协作就清楚了:

```
浏览器(Vue 页面)
   │  用户点击"保存房间"
   ▼
api/room.ts ── axios(request.ts 拦截器自动附带 Authorization: Bearer <JWT>)
   │  PUT /api/rooms/12        (开发期经 vite 代理转到 8080;生产经 nginx)
   ▼
后端 AuthInterceptor ── 校验 JWT,把当前用户放入 ThreadLocal;白名单(登录/接口文档)直接放行
   ▼
RoomController(PUT /rooms/{id}) ── @Valid 参数校验
   ▼
RoomServiceImpl ── 业务逻辑(如房号唯一性检查),违规抛 BusinessException
   ▼
RoomMapper(MyBatis-Plus) ── SQL
   ▼
MySQL(room 表)
   │  返回结果
   ▼
统一响应 ApiResponse{code:0, message:"ok", data:{...}}
   │  任一环节抛异常 → GlobalExceptionHandler 兜住,转成对应 code 的 ApiResponse
   ▼
前端响应拦截器:code=0 → 返回 data;401 → 清 token 跳登录;其他 → ElMessage 报错
   ▼
页面刷新表格,用户看到结果
```

**为什么这样设计**:统一入口(拦截器)、统一出口(统一响应+全局异常)、统一约定(错误码),任何模块加进来都走同一条路——这是"填空"可行的前提。

## 2. 后端骨架设计

### 2.1 包结构(沿用已建目录)

```
com.anes.schedule
├── ScheduleApplication.java     # 启动入口(已有)
├── common/                      # ★ 公共底座(骨架核心)
│   ├── ApiResponse.java         #   统一响应 {code, message, data}
│   ├── ErrorCode.java           #   错误码枚举(见 2.2)
│   ├── BusinessException.java   #   业务异常(带 ErrorCode)
│   ├── GlobalExceptionHandler.java  # @RestControllerAdvice 全局兜底
│   ├── PageResult.java          #   分页结果封装
│   ├── AuthContext.java         #   ThreadLocal 当前用户(userId/role/staffId)
│   └── JwtUtil.java             #   JWT 签发/解析(HS256)
├── config/
│   ├── WebMvcConfig.java        #   注册拦截器 + 排除路径
│   └── OpenApiConfig.java       #   Swagger 文档配置
├── controller/                  # 每模块一个 XxxController
├── service/                     # 每模块一个 XxxService(接口)+Impl?→ 单实现直接类,不强行接口
│   └── engine/                  #   排班引擎(ScheduleStep 管道,见 2.6)
├── mapper/                      # 每模块一个 XxxMapper extends BaseMapper<Xxx>
├── entity/                      # 每模块一个实体,@TableName 对应表
└── dto/                         # 每模块的请求/响应对象(XxxCreateReq、XxxUpdateReq、XxxResp)
```

> 约定:Service 单实现不写接口(避免无意义样板);entity 不出 controller,出入一律 DTO。

### 2.2 统一响应与错误码

```
ApiResponse<T> { int code; String message; T data; }
```

| code | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | 正常返回 |
| 401 | 未登录/token 失效 | AuthInterceptor 拦截 |
| 403 | 无权限 | 普通成员调管理接口 |
| 400 | 参数/业务校验失败 | @Valid 校验失败、BusinessException |
| 500 | 系统异常 | 兜底,日志记录完整堆栈 |

GlobalExceptionHandler 处理顺序:BusinessException → 对应 code;MethodArgumentNotValidException → 400 + 字段错误明细;Exception → 500(不向前端泄露堆栈)。

### 2.3 认证(JWT)

- `POST /api/auth/login` {username, password} → 校验(BCrypt)→ {token, user:{name, role}};失败返回 401
- 密码存储:`spring-security-crypto` 的 BCryptPasswordEncoder(**只引 crypto 这一个 jar,不引整个 Spring Security**)
- JwtUtil:HS256 签发,有效期 12h(配置 `jwt.expire-hours`),claims 含 userId/role
- AuthInterceptor:白名单 = `/auth/login`、Swagger 相关(`/v3/api-docs/**`、`/doc.html`、`/swagger-ui/**`);其余校验 `Authorization: Bearer xxx`,通过后 `AuthContext.set(user)`,`afterCompletion` 里 remove(防线程复用串号)
- 种子账号:schema.sql 增加 `admin`(ADMIN 角色,BCrypt 初始密码,首次交付后改密)

### 2.4 接口文档(Swagger / OpenAPI)

- 依赖 `springdoc-openapi-starter-webmvc-ui`,访问 `http://localhost:8080/api/swagger-ui.html`
- **填空规范**:每个 Controller 加 `@Tag(name="房间管理")`,每个接口一句 `@Operation(summary="新增房间")`,DTO 字段 `@Schema(description="房号")`——你逐步完善模块时,接口文档自动同步,前后端联调与自查全靠它

### 2.5 样板模块:房间管理(照抄模板)

所有后续模块照此结构填空:

| 文件 | 内容要点 |
|---|---|
| `entity/Room.java` | @TableName("room"),字段对应表,MyBatis-Plus 注解 |
| `mapper/RoomMapper.java` | `extends BaseMapper<Room>`,空接口即可 |
| `dto/RoomDtos.java` | RoomCreateReq(code/area 必填)、RoomUpdateReq、RoomQuery(area、keyword、pageNum、pageSize)、RoomResp |
| `controller/RoomController.java` | `GET /rooms`(分页+筛选)、`POST /rooms`、`PUT /rooms/{id}`、`DELETE /rooms/{id}`(ADMIN)、`GET /rooms/{id}`;@Tag/@Operation 标注 |
| `service/RoomService.java` | CRUD + 规则:code 唯一(重复抛 BusinessException 400);删除前校验未被布局/排班引用 |
| `RoomControllerTest 之类暂不写` | Controller 层不做集成测试;业务规则多了再补单测 |

### 2.6 扩展点(SPI,模块热插拔的关键)

```java
// 规则中心:每种 rule_type 一个实现,Spring 自动收集
public interface RuleHandler {
    String ruleType();                    // 如 "OR.ADJACENCY_PREF"
    EngineHook hook();                    // 挂载点(管道步骤枚举)
    void apply(RuleContext ctx);          // 解释 payload、影响排班上下文
}
// 排班引擎:管道步骤,实现类按 order() 排队执行
public interface ScheduleStep {
    String name();                        // 如 "值班组"、"手术室分配"
    int order();
    void execute(ScheduleContext ctx);    // 读上一步产出,写本步骤结果
}
```

RuleRegistry/SchedulePipeline 用 `List<RuleHandler>`/`List<ScheduleStep>` 构造注入自动装配——**加规则/加步骤 = 新增一个类,不改现有代码**。

## 3. 前端骨架设计

### 3.1 目录职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `api/` | 每模块一个文件(room.ts、staff.ts…),只写接口调用 | 任何 UI 逻辑 |
| `stores/` | Pinia:auth.ts(登录态) | — |
| `router/` | 路由表 + 守卫 | — |
| `components/` | 跨页面复用组件(MainLayout、后续排班矩阵、画布) | 单页面私有组件(放 views 同目录) |
| `types/` | 每模块 TS 类型(与后端 DTO 对应) | — |
| `views/` | 页面,按模块分子目录 | — |

### 3.2 主布局与路由

- `components/layout/MainLayout.vue`:左侧菜单(**按角色过滤**:ADMIN 全量——工作台/月度表/总览/我的/人员/房间/规则/布局;USER 只见 总览/我的)+ 顶栏(当前用户名、退出登录)+ `<router-view/>`
- 路由改为嵌套:`/login` 独立;其余挂在 MainLayout 下
- 守卫(`router.beforeEach`):无 token → `/login?redirect=...`;`meta.requiresAdmin` 的路由对 USER 弹提示并回总览

### 3.3 axios 封装(request.ts 升级)

- 请求拦截:自动附 `Authorization: Bearer ${token}`
- 响应拦截:`code===0` 直接返回 `data`;`401` → 清 auth store、跳登录;其余 → `ElMessage.error(message)` 并 reject

### 3.4 样板页面:房间管理(照抄模板)

`api/room.ts` + `types/room.ts` + `views/admin/RoomView.vue`:

- 筛选栏:区域下拉(取自后端去重)+ 房号关键字 + 查询/重置
- `el-table`:房号、区域、星标(el-switch 行内切换)、参与排班(el-switch)、更新时间、操作列(编辑/删除)
- `el-pagination` 分页
- 新增/编辑共用 `el-dialog` + `el-form`(rules:房号必填、区域必选)
- 删除:`ElMessageBox.confirm`
- 全部成功/失败提示走统一拦截,页面不重复写
