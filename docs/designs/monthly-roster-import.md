# Design: 步骤3 月度值班备班表导入(最小数据通路)

## Problem Statement

麻醉科的月度值班备班表(值班 1老总+1二档+1三档+1四档、长接班、短接班顺序、备班1/2、副麻接班、副麻中班)目前由总值班每月用 Excel 手工维护;旧系统只能部分自动读取(副麻仅 8 人),其余靠手动调整。步骤 4 排班引擎必须有结构化的月表数据才能运转——本模块就是这条数据通路:把真实月表 Excel 读准、存对。

## Demand Evidence

- 推动者=开发者本人(科室/信息科人员),需求链真实不失真:访谈确认口径、418 人真实档案、89 间手术室清单均来自科室真实数据。
- 旧系统受限是当事人亲述口径("改动工程浩大,只能自动读取8个副麻")。
- 诚实记录的弱点:**首个真实用户尚未确定**(D2 答复"还没确定"),验收人缺位,已列入前提与作业。

## Status Quo

总值班每月手工整理 Excel 月表 → 旧系统部分读取 + 大量手动修改 → 手术分配还要去 HIS 手动调整。月表是排班流程的源头数据,却停留在"人肉 Excel + 半自动旧系统"状态,无校验、无追溯。

## Target User & Narrowest Wedge

- 过渡期操作者:开发者本人(代运维,每月代上传月表);种子用户:一位总值班(待物色,见 The Assignment)。
- 最窄楔子(A 方案):上传真实月表 → 解析 → 预览校验修正 → 入库;同月重传即替换。不做在线编辑,不改变科室任何习惯。

## Constraints

- 解析器适配科室**现有**月表格式(可能含合并单元格/多 sheet),不强制换模板(前提 D6 已确认);**模板下载功能不做**(D6 的直接推论;占位页现文案"在线表格编辑(实施步骤 3 开发)"与 A 方案不符,实现时同步改为"Excel 导入与预览校验")。
- 技术栈与既有底座:Vue3 + Element Plus / Spring Boot 3 + MyBatis-Plus + EasyExcel;schema 已定(`monthly_roster`:roster_month/status/created_by,无 version 列 / `monthly_roster_item`:duty_date 当日固定 + seq 顺序池双形态)。
- 人员匹配以工号为唯一键、同名消歧(复用步骤 2 的匹配规则,假设 A6):月表单元格按**姓名**读入——唯一名直接解析到档案,同名(库内 8 对)出候选由人工选择,单元格含工号则优先用工号。匹配范围仅 `active=1` 人员,命中停用人员按"未匹配"处理并特殊提示。
- 院内网部署,无外网依赖;非 xlsx/xls、加密、损坏文件统一按"解析失败"错误返回。

## Premises(问诊已确认)

1. 适配真实表格式,不强推系统模板(D6=同意)。
2. 沿用既有 schema 双形态落库,步骤 4 引擎直接消费。
3. 复用步骤 2 已验证的**工号唯一键匹配、同名提示、结果报告**;预览确认与行号回传为本期新建(步骤 2 是单阶段导入,无预览界面,不存在可直接搬用的参照物)。
4. 首个用户未定 → 交付后开发者代运维过渡,尽快拉一位总值班做种子用户(D7=同意)。
5. 本步骤只做"读对 + 存对",不做排班逻辑(步骤 4)与在线编辑(按需后补)。

## Approaches Considered

### Approach A: 最小数据通路(选定)
上传 → 解析(EasyExcel + 真实格式适配)→ 预览页校验修正(人名候选/岗位映射/日期对齐)→ 入库;同月重传整月替换。
- Effort: S-M(人工约 6-10 天,为**新建**预览修正链路(步骤 2 无可搬用件)+ 合并单元格语义重建的口径 / CC 约 2-3 轮会话);Risk: Low-Med
- ✅ 引擎(核心价值)的最短前置路径;预览修正兜住解析误差;替换语义简单
- ❌ 月中改表需改 Excel 后重传;无在线微调
- ❌ 无历史版本:重传即整月覆盖,追溯靠人工留存 Excel(痛点被承认但在 A 中不解决)
- ❌ 模板下载不做(前提 D6 推论)

### Approach B: 完整闭环(原计划范围)
A + 在线表格编辑 + 月表版本管理(DRAFT/ACTIVE/历史)。
- Effort: M-L(人工约 2-3 周);Risk: Med
- ✅ 兑现实施规划原定范围;总值班无需回 Excel
- ❌ 编辑器是本期最大工作量,挤占步骤 4 排期;为未定用户过度建设

### Approach C: 体检报告优先
只做解析 + 校验报告,不暴露入库界面。
- Effort: S;Risk: Low
- ✅ 科室零习惯改变,总值班立刻受益
- ❌ 引擎需要的入库通路没有建立,步骤 4 仍需返工补

## Recommended Approach

**A(最小数据通路),B 的在线编辑等真实用户反馈后按需追加。**

### 设计要点

**两阶段交接(parse → import)**:
- `POST /roster/parse?month=YYYY-MM`(month 由用户上传时选择):仅解析,返回完整行集合(每行含 sheet 名 + Excel 物理行号)+ 校验问题清单,**不入库**
- `POST /roster/import?month=YYYY-MM`:前端回传**完整修正后行集合**(行以 parse 返回的行号标识;两阶段链路为本期新建),服务端复核——发现阻断项则 400 返回问题清单、**整体拒绝、零部分提交**,通过则入库
- 月份规则:目标月以用户选择为准;文件内可解析出的月份仅做一致性校验,不一致列为**阻断**问题;允许导入历史月(补数据)
- 权限:月表解析/导入/替换仅 ADMIN(总值班)可执行——后端 `requireAdmin()` 拦截,前端入口按角色过滤(与既有管理页一致)

**落库与替换**:
- 10 类岗位全部落库(值班 4 档 + 备班 2 类 + 接班/中班 4 类),形态归属表(样本到位前为默认约定,可校准):

| position_type | 形态 | 说明 |
|---|---|---|
| ON_CALL_CHIEF / ON_CALL_T2 / ON_CALL_T3 / ON_CALL_T4 | duty_date 按日 | 值班四档 |
| STANDBY1 / STANDBY2 | duty_date 按日 | 备班每日轮换 |
| SHORT_RELIEF | seq 顺序池 | 短接班按序顺延(唯一明确有序) |
| LONG_RELIEF | duty_date 按日(默认,待样本校准) | 长接班 |
| ASSISTANT_RELIEF / ASSISTANT_MID | duty_date 按日(默认,待样本校准) | 副麻接班"周一~四复制前日"是引擎读取时的语义,月表按日存 |

- 同月重传替换:事务内旧 item 全删重插,`monthly_roster.status` **导入即 ACTIVE**(A 方案无草稿态),幂等口径=替换后业务数据等价即可(item 自增 id 允许变化)
- 下游影响:替换不自动失效已生成的排班快照;工作台在月表 updated_at 晚于快照生成时间时提示"月表已更新,建议重新生成"(一期一句话提示即可)

**预览校验清单(分级)**:
- **阻断**(必须修正才能入库):解析行集合为空(空表/仅表头);任何无法映射的单元格/合并区域(生成"无法解析"问题行,**禁止静默丢弃**);工号/姓名未匹配且未在预览中修正;月份不一致;日期越界(相对目标月实际天数,含闰年 2 月);seq 重号
- **警告**(提示但可入库):同名不同工号提示;顺序池断号;值班四档缺人日(默认警告——周末/节假日是否必须四档待科室确认,列入待确认);可疑同人同日多岗(注意:**备班1×短接班顺序池首人是合法业务形态**,业务规则明确由下一人顶上,不报)

**预览可修正项白名单**(防止滑向 B 方案):人名候选选择、岗位映射修正、日期对齐修正;其余问题一律回 Excel 修改后重传。

**解析适配层**:
- 按真实样本定义 sheet/列/合并单元格映射规则(先常量,格式频繁变化再升级配置)
- EasyExcel 默认读取合并区域只有左上格有值;复杂表预留 **POI 直读通道**(`getMergedRegions()` 坐标→语义重建;POI 是 EasyExcel 的传递依赖,**无需新增依赖**),首版目标=目标样本 100% 可解析,不求普适

**其余接口**:`GET /roster/{month}`(按日/按岗位/顺序池的查询 DTO,供步骤 4 引擎与前端查看)

## Open Questions

1. 真实月表的确切结构(样本到位后校准解析适配层与三类 TBD 岗位形态;短接班顺序在表中的呈现方式是重点)
2. 月表是否有多 sheet/多月并存(影响解析入口)
3. 周末/节假日值班四档是否必须齐全(决定"四档缺人日"是警告还是阻断)

## Success Criteria

- 用真实月表样本导入成功,10 类 position_type(ON_CALL_CHIEF/ON_CALL_T2/ON_CALL_T3/ON_CALL_T4/STANDBY1/STANDBY2/SHORT_RELIEF/LONG_RELIEF/ASSISTANT_RELIEF/ASSISTANT_MID)正确落库,步骤 4 引擎可按日查询值班/备班/接班安排
- 首版以"目标真实样本 100% 可解析"为验收线;人工修正行占比 ≤5%,记录为基线(测量口径:修正行数/总数据行数,以首份样本试导入为准)
- 同月重传替换后业务数据等价,不产生重复
- 预览校验问题可操作(问题定位到 sheet+物理行号,阻断项有修正手段)
